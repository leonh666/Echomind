# 模型输入与输出预算

适用于当前 Python EchoMind 服务。默认值集中在 `core/llm_limits.py`。
`max_tokens` 是每次模型调用的最大输出预算，不是要求模型输出这么长；
兼容供应商如果把推理内容也计入输出预算，推理会占用其中一部分。

## 输出预算

| 调用 | 原默认值 | 新默认值 | 可选环境变量 |
| --- | ---: | ---: | --- |
| 意图识别 | 256 | 4096 | ECHOMIND_INTENT_MAX_TOKENS |
| 查询改写 | 256 | 4096 | ECHOMIND_QUERY_REWRITE_MAX_TOKENS |
| 检索重排 | 256 | 4096 | ECHOMIND_RERANK_MAX_TOKENS |
| 质量评判 | 256 | 4096 | ECHOMIND_JUDGE_MAX_TOKENS |
| 画像提炼 | 4096 | 4096 | ECHOMIND_PROFILE_MAX_TOKENS |
| 对话摘要 | 256 | 8192 | ECHOMIND_SUMMARY_MAX_TOKENS |
| 摘要合并 | 256 | 8192 | ECHOMIND_SUMMARY_MERGE_MAX_TOKENS |
| 通用客服 | 900 | 8192 | ECHOMIND_GENERAL_MAX_TOKENS |
| 技术支持 | 1200 | 8192 | ECHOMIND_TECHNICAL_MAX_TOKENS |
| 账单服务 | 1100 | 8192 | ECHOMIND_BILLING_MAX_TOKENS |
| 多 Agent 汇总 | 1000 | 8192 | ECHOMIND_COMPOSER_MAX_TOKENS |
| 人工交接角色配置 | 500 | 4096 | ECHOMIND_ESCALATION_MAX_TOKENS |

人工交接当前使用固定流程，不调用模型；其角色配置仍一并扩大。
自定义 AgentProfile 的默认输出预算从 1024 提高到 8192。
这些环境变量在调用时读取，只接受正整数；非法值回退默认值。
已有显式配置会覆盖新默认值，可以按实际模型能力继续调整。

## 输入范围

| 输入位置 | 原范围 | 新范围 |
| --- | --- | --- |
| 意图识别历史 | API 最近 5 条，模型取其中 3 条 | 两处统一最近 10 条 |
| Agent 的记忆上下文 | 最近 8 条消息、3 条相关历史 | 最近 20 条消息、5 条相关历史 |
| 画像提炼对话 | 最近 10 条 | 最近 20 条 |
| 会话摘要保存长度 | 800 字符 | 4000 字符 |
| 情景记忆原文元数据 | 前 500 字符 | 前 8000 字符 |
| 重排时每项检索内容 | 前 200 字符 | 前 4000 字符 |
| 单个 Skill 正文 | 3200 字符 | 8000 字符 |
| 匹配 Skills 总预算 | 5000 字符 | 16000 字符 |
| 工具关注点 / 环境 / 交接理由 | 40 / 80 / 120 字符 | 512 / 1024 / 2048 字符 |

单个 Skill 和总预算分别支持 `ECHOMIND_SKILL_MAX_CHARS`、
`ECHOMIND_SKILLS_MAX_PROMPT_CHARS`。消息条数是输入的最多条数，
压缩后仍保留最近 5 条原消息，其余内容通过摘要和相关历史补充。
意图缓存改为根据完整消息和实际使用的最近 10 条历史计算键，
避免长消息前 200 字相同、后文不同却错误复用分类结果。
知识库的 500 字分块会把全文拆成多块，不是只保留前 500 字，因此保留原设置。

## 截断与失败处理

所有模型调用在接受输出前检查 `stop_reason=max_tokens`，正文路径还检查空文本。
即使截断响应里恰好有可解析的 JSON，也会进入原有失败处理：
意图使用本地策略，改写保留原查询，重排保留原顺序，汇总保留专业回复，
质量评判标记失败，画像保留旧数据。Agent 不把截断回复标记为成功，
也不执行截断响应里的工具请求。

对话摘要生成失败、被截断或没有正文时，跳过压缩并保留 Redis 原消息。
摘要合并失败时，仍使用扩大到 4000 字符的拼接兜底。

提高预算只能降低截断概率，不能保证任意长输入或推理都能容纳；
供应商的上下文窗口、最大输出限制和网络错误仍独立生效。
更长的实际输入和输出可能增加耗时与费用。
更新源码后需要重启服务；Docker 镜像部署需要重新构建应用镜像。
