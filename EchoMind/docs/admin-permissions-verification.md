# 管理员与普通用户隔离：本地验收记录

验收日期：2026-10-22。主链路仍为原生 Python，未引入新的 Agent 框架。

## 实现范围

- admin 可分页查看本组织用户、审计、会话索引、全部任务与工单，保留知识、评测和监控入口。
- customer 页面仅显示个人信息、对话与本人工单；后台、调试、审计、知识管理、评测和运行指标接口拒绝其访问。
- support 保留本组织工单处理和工单审计；kb_admin 保留授权知识管理，均无完整组织后台权限。
- 每次请求根据数据库现有成员关系认证，角色/组织不取自客户端。组织管理员也不能跨组织读取业务数据。
- 用户字段、审计详情和后台任务载荷采用允许字段清单；不返回密码、盐、会话令牌或确认执行凭据。
- 退出、切换身份、权限失效时清空私人内容，防止旧异步请求重新填充数据。前端默认只启用 Python 后端。
- 指标改为管理员会话或专用抓取凭据访问；抓取凭据仅对 metrics 生效。Compose 数据端口仅本机开放，监控 secret 不进入 Git 或构建镜像。

## 验证结果

| 验证 | 结果 | 条件 |
|---|---|---|
| Python 应用及 benchmark 测试 | 381 项通过 | Python 3.12；模型/Chroma 测试替身，真实临时 SQLite；Windows 本机异步测试 |
| 前端 Node 测试 | 31 项通过 | 含请求权限、字段过滤、分页、身份切换、延迟响应与旧聊天清理 |
| Vite 生产构建 | 通过 | 现有本地依赖；默认 Python 配置 |
| 页面验收 | 通过 | 仅监听本机的临时服务；合成账号与独立数据库，无真实客户数据 |
| 双 Compose 配置 | YAML 结构及 secret/端口一致性检查通过 | 未运行 Docker，未替代容器实际启动验收 |

页面检查包括：管理员看到同组织三个合成账号；27 条任务按每页 20 条翻页，第二页能看到已提交任务；退出后后台消失；客户 alice 个人页显示自己的资料，工单页只有 alice 的记录，没有 bob 的记录与后台入口。

HTTP 测试另覆盖：伪造角色/组织、尾斜杠、应用路由前缀、关闭旧聊天鉴权时的后台保护、跨用户/跨组织猜测 ID、角色降级即时失效、后台字段过滤、监控文件凭据优先级与凭据缺失拒绝。

## 复验

在已按 requirements.txt 安装后端依赖的环境中运行：

```bash
cd EchoMind
python -m pytest tests evaluation/benchmark_v1/tests -q -p no:cacheprovider
```

前端：

```bash
cd EchoMindFrontend
node --test tests/*.test.js
npm run build
```

首次 Compose 启动新增监控 secret 准备步骤，见 [权限说明](../wiki/管理员与用户权限说明.md)。没有创建默认生产账号，没有改动本地真实 .env，也没有提交或发布 API Key。

这份记录证明权限与工程行为的本地验证。没有调用付费模型、测量 Agent 真实完成率、重新部署云端、运行 Docker 或完成真实依赖压测。
