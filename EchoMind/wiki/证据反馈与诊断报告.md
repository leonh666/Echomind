# 证据、反馈与客服诊断报告

保持原生 Python + FastAPI + SQLite + Vue，不引入新的 Agent 框架。支持商家辅助试点，记录实际回答、检索证据与人工修改，并生成可复核的阶段报告。本功能不自动连接小红书或向外部平台发送消息。

## 使用流程

1. 登录并完成一轮聊天，在“检索来源”核对产品版本、文档版本、知识库、更新时间、有效期、片段位置、原文链接。未提供的资料字段显示“未提供”。
2. 展开反馈，明确选择直接采纳、修改后采纳或弃用。修改/弃用需要原因；修改需填写实际采用的回复。复制按钮不会自动计为采纳，也不会对外发送。
3. 单独填写解决结果，默认“尚未确认”。顾客停止追问不会自动判为已解决。
4. “我的咨询”支持重新查看本人回答、证据和反馈。客服角色可复核本组织咨询；管理员可查看本组织咨询并生成诊断报告。知识库管理员的咨询历史仍仅限本人。
5. 管理员进入“客服诊断”，选择最近 7/14/30 天，生成并保存报告，查看问题分布、待复核案例、来源使用情况，或导出 Markdown。

咨询详情显示当前反馈，历史报告保持生成时快照。更新反馈后，应重新生成报告查看变化。升级前未保存快照的旧聊天不会自动补录；匿名开发模式不保存回答或接受匿名反馈。

## 证据和反馈

- 由聊天服务器保存原问题、回答、实际来源、业务分类、警告和响应耗时。反馈接口不接受问题、原回答、来源、用户或组织等可伪造字段。
- 原回答与来源不可覆写，反馈保存最新版本，同时追加保存修改记录并记录操作审计。反馈版本过期时返回冲突，界面保留编辑并要求重新载入。
- 来源只保留允许展示的字段，不暴露任意元数据或内部组织字段。原文链接只允许无嵌入账号密码的 HTTP/HTTPS；片段超过 6000 字符明确标注截断。
- 检索分数/距离用于排序，不是答案正确率。当前展示检索证据，不声称已经完成逐句引用核验或忠实性评测。
- 正式试点前应明确文本记录用途、模型服务商数据流向、脱敏规则与保留周期。数据库和包含真实咨询的报告不应提交到公开仓库。

## 报告统计口径

报告由确定性的 Python 统计和规则生成，不额外调用模型，也不自动更新知识库、提交工单或执行经营动作。

| 指标 | 分子 | 分母 |
|---|---|---|
| 反馈覆盖率 | 有最新反馈的回答数 | 全部已保存回答数 |
| 直接采纳率 | 最新反馈为直接采纳的回答数 | 有反馈的回答数 |
| 修改采纳率 | 最新反馈为修改后采纳的回答数 | 有反馈的回答数 |
| 弃用率 | 最新反馈为弃用的回答数 | 有反馈的回答数 |
| 已知结果中的解决率 | 人工标记已解决的回答数 | 人工标记已解决或未解决的回答数 |

- 页面和导出同时展示分子、分母。分母为零时返回 `value: null`，显示“暂无有效样本”，不显示为 0% 或 100%。
- 每条回答只统计最新一版反馈，反复修改不增加样本数。反馈是人工观察，不是独立正确性核验；未反馈或未确认解决均为未知。
- 按回答保存时间筛选，使用 UTC Unix 时间戳及 `[start_at,end_at)` 左闭右开区间。最近 N 天表示滚动 N×24 小时，页面按浏览器本地时区显示。
- 反馈截至报告生成时刻，可以包括咨询之后补录的处理结果。重新生成同一咨询时间窗可能因反馈变化而不同，已经保存的旧报告不变。
- 汇总覆盖整个时间窗内本组织的全部回答，不用分页前 20 条或向量 Top-K 代替总体。问题示例最多 20 条，高频原文与来源各最多 10 项。
- 无来源、检索警告或转人工且未反馈的回答进入优先复核队列。无来源不自动判为知识缺失；“缺少知识”统计来自人工明确标注。
- 高频问题对空白归一后的原文精确计数，尚未进行语义聚类。同一回答的同一文档版本命中多个片段，来源使用次数仅计一次。
- 平均/P95 响应耗时包括记忆读取、识别、检索、生成、记忆写入，不含人工审核、复制、对外发送及新快照落库耗时。
- 只统计成功保存的回答，不含失败、超时或取消的请求，不能当作系统成功率。小样本用于发现问题，不证明稳定业务效果。

## 接口与权限

全部接口要求登录，即使关闭开发环境聊天鉴权也不接受匿名调用。

| 接口 | 用途 | 权限 |
|---|---|---|
| `GET /answers?limit=20&offset=0` | 分页咨询历史 | 普通用户/知识库管理员仅本人；客服/管理员本组织 |
| `GET /answers/{request_id}` | 原回答、来源与当前反馈 | 同上，无权访问返回 404 |
| `PUT /answers/{request_id}/feedback` | 保存反馈 | 同上，带当前反馈版本 |
| `POST /diagnostics/reports` | 生成并保存诊断 | 本组织管理员 |
| `GET /diagnostics/reports` | 分页报告历史 | 本组织管理员 |
| `GET /diagnostics/reports/{id}` | 冻结报告详情 | 本组织管理员，跨组织返回 404 |

首次反馈使用 `revision: 0`，后续使用服务器返回的当前版本。不同内容的旧版本提交返回 `409 feedback_conflict`；同一操作者重试刚刚成功的相同请求返回已有结果。

```json
{
  "revision": 0,
  "decision": "edited",
  "reason": "incomplete",
  "final_answer": "请提供商品型号，以确认适用的清洗方式。",
  "comment": "原回答遗漏型号条件",
  "outcome": "unknown"
}
```

报告请求为 `{"days": 7}`；API 支持 1～90 天及可选过去/当前 `end_at`。业务诊断与 `/eval/reports` 离线评测报告分开管理。

## 存储和升级

使用 `ECHOMIND_BUSINESS_DB_PATH`，默认 `EchoMind/data/business/echomind.sqlite3`。启动时追加新表，保留已有 schema v1 的用户、工单与审批记录：

- `answer_snapshots`：不可变的回答和来源；
- `answer_feedback`：每条回答最新反馈；
- `answer_feedback_history`：每次修改记录；
- `diagnostic_reports`：报告快照。

升级前先备份业务数据库，继续使用 `python -m business.maintenance backup`，完整备份包含新表。API Key 仍仅由服务端环境读取，不发送到浏览器、不进入报告或 Git。

自动化覆盖持久化/重启、并发反馈、重复提交、身份与组织隔离、原回答不可覆写、零分母、最新反馈去重、半开时间窗、全量统计和报告快照不变。前端覆盖校验、凭据、取消信号及身份/角色改变后的迟到响应丢弃。

验收使用独立 SQLite、合成账号和假模型，不代表已经接入真实商家、完成公网部署或验证真实模型效果。
