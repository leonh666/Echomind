# 用户名登录与注册

登录栏提供“没有账号？立即注册”，使用用户名、密码、确认密码注册，成功后返回登录表单。用户名为 3–32 位英文字母、数字或下划线，不区分大小写；密码为 12–1024 个字符。前端检查两次密码一致，后端校验格式与唯一性。登录状态仍使用 HttpOnly Cookie，不在浏览器持久化令牌。

新注册账号固定为 `customer`，只能访问自己的咨询、资料和工单。注册请求不能传入角色、邮箱或组织编号。登录与注册共享每个应用进程、每个来源 IP 每分钟 10 次的预算；保留请求来源检查。多实例部署应在网关补充统一限流，当前预算不是全局限流。

后端 `.env` 中 `ECHOMIND_REGISTRATION_ENABLED=false` 可关闭注册。默认开启；`ECHOMIND_REGISTRATION_ORGANIZATION_ID` 为空时，账号进入独立的 `self-service` 客户工作区，不会自动加入已有商家的组织。已有商家试点应将此变量填写为该商家的组织编号，重启后端，确保商家管理员能在本组织后台管理新用户。未配置时，原组织管理员不会看到 `self-service` 的用户。服务端配置的组织不存在时拒绝注册。

首次打开新版业务数据库会在事务中补充唯一用户名，保留用户编号、原密码、组织成员关系和有效会话。通常由旧邮箱前缀生成，例如 `admin@example.invalid` 对应 `admin`；非法字符改为下划线，前缀重复时追加 `_1` 等后缀，太短时生成 `user_` 标识。可继续使用原邮箱登录，并在“我的信息”查看自动分配的用户名。现有显示名称不会作为身份凭据。

本机管理员仍由可信 CLI 开通，可通过 `--username` 显式指定用户名：

```powershell
docker compose exec echomind python -m business.auth --db /app/data/business/echomind.sqlite3 create-user --email admin@example.invalid --username shop_admin --organization-name Demo --role admin
```

当前数据库保留邮箱列以兼容旧数据。无邮箱注册账号在内部使用随机 `@accounts.invalid` 标识占位，不发送邮件，也不提供邮箱找回密码；面向用户展示用户名。管理员开通账号保留邮箱参数。密码找回、邮箱验证和邀请制加入其他组织尚未实现。

更新界面及后端，在 `D:\EchoMind\EchoMindFrontend` 执行：

```powershell
docker compose --env-file ../EchoMind/.env --env-file .env up -d --build
```
