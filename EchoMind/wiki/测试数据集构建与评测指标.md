## 2. 为什么不能直接找一个公开集代替项目评测

EchoMind 同时涉及中文意图、知识检索、版本条件、多轮指代、拒答、工具与业务状态。
公开基准通常只覆盖其中一部分，语言、标签、工具协议和业务规则也未必匹配。
把银行意图强行合并成通用账单标签，或把英文问句译成中文后直接沿用原成绩，都改变了任务定义。
大数据量本身不能证明业务覆盖；可追溯的来源、明确标签和能够核对的终态更有价值。

本轮采用“自定义中文客服集为主、公开基准单独辅助”的方式。
公开基准用来借鉴任务结构、补充外部分布或做独立对照，不与自定义集合混成一个总分。
当前交付没有捆绑下述公开基准的数据行，也没有使用用户聊天记录、真实账号或企业工单。

## 3. 公开基准调研与许可核对

以下说明基于原作者仓库、论文或官方文档；引入数据时还要固定所用 revision，并保存来源、原始划分和许可记录。
“可下载”与“适合直接导入 EchoMind”是两个判断；代码许可也不自动覆盖外部语料。

### 3.1 CLINC150

[原作者仓库](https://github.com/clinc/oos-eval)用于意图分类和域外请求检测，包含 150 个域内意图。
原数据全部为英文、单意图，通过众包场景和改写生成，不能描述成真实生产客服日志。
它适合研究分类边界和 OOS，但原 OOS 只相对于原标签空间成立，不自动等于 EchoMind 的 other。
不建议直接并入中文主集；中文改编时保存原 ID、翻译或改编说明及新的标签映射。
[原仓库 LICENSE](https://raw.githubusercontent.com/clinc/oos-eval/master/LICENSE)已核验为 CC BY 3.0，分发时保留来源署名和改动说明。

### 3.2 BANKING77

[原作者仓库](https://github.com/PolyAI-LDN/task-specific-datasets)包含 77 类银行意图，训练集 10,003 条、测试集 3,080 条。
它适合细粒度意图混淆分析，但英文银行业务与本项目的通用客服分类不同。
例如银行卡到达、转账取消不能未经审核就映射成演示设备物流或一般请求。
可单独保留原标签评测；映射或抽样后的结果应标为改编实验，不称原版 BANKING77 成绩。
[原仓库 LICENSE](https://raw.githubusercontent.com/PolyAI-LDN/task-specific-datasets/master/LICENSE)已核验为 CC BY 4.0。

### 3.3 MASSIVE 中文

[官方仓库](https://github.com/alexa/massive)与[AmazonScience 数据说明](https://huggingface.co/datasets/AmazonScience/massive)包含 zh-CN、zh-TW，提供意图和槽位标注。
它主要源于通用语音助手单轮交互的本地化，60 类意图、55 类槽位不是客服工单标签。
可抽样建立独立中文域外请求或实体辅助集，不建议把全部类别强行映射为本项目标签。
中文本地化数据不能包装为中国真人客服会话；原样本及其跨语言对应项也不能跨开发、测试集合泄漏。
[NOTICE](https://raw.githubusercontent.com/alexa/massive/main/NOTICE.md)明确数据为 CC BY 4.0；[代码 LICENSE](https://raw.githubusercontent.com/alexa/massive/main/LICENSE.txt)为 Apache 2.0。

### 3.4 BEIR

[官方仓库](https://github.com/beir-cellar/beir)汇集不同领域检索任务，可借鉴 corpus、queries、qrels 及排序结果的组织方式。
它适合比较检索器，不直接提供中文客服意图、回答或工单验收集。
优先借鉴评测结构；如另选子数据集做外部实验，单独保存结果，不混入本项目知识事实。
[工具 LICENSE](https://raw.githubusercontent.com/beir-cellar/beir/master/LICENSE)已核验为 Apache 2.0；各子数据集许可需分别核查，本次没有完成全部子集许可核验。
官方 README 也明确要求使用者确认具体语料的使用权限，不能笼统写“BEIR 数据都是 Apache 2.0”。

### 3.5 Ragas

[官方指标文档](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/)提供 RAG、回答和工具评测方法；它是评测工具与方法，不能当作现成客服题库。
可选接入 Faithfulness 等指标，但需要实际模型上下文、明确字段、中文评分校准和错误记录。
Ragas 产生的评分不能代替业务数据库核对；生成的测试题仍需标记来源与人工复核状态。
[当前官方仓库 LICENSE](https://raw.githubusercontent.com/vibrantlabsai/ragas/main/LICENSE)已核验为 Apache 2.0，不能据此推断外部数据或模型都使用相同许可。

### 3.6 τ-bench 旧版

[原始论文](https://arxiv.org/abs/2406.12045)和[旧版官方仓库](https://github.com/sierra-research/tau-bench)强调规则、用户模拟、API 工具及最终数据库状态。
它适合借鉴业务任务评测，不适合直接转成静态中文问答；其模拟用户和生成数据不能算真实客户样本。
原版航空、零售工具与 EchoMind 不兼容，需建立独立适配环境才可报告该基准成绩。
旧仓库当前提示任务过时并指向后续版本；本次只参考旧版方法，没有声称运行最新版。
[旧版仓库 LICENSE](https://raw.githubusercontent.com/sierra-research/tau-bench/main/LICENSE)已核验为 MIT；后续版本与附加资源许可没有在本次全部核验。

## 5. 划分、来源与泄漏控制

划分单位是 group_id 所标识的来源家族或场景家族，同一家族的改写不跨 dev/test。
RAG 同主题的版本文档和问题归同一来源家族；意图改写与契约场景也有各自的分组。
dev 用于调参和发现问题；test 冻结后用于最终比较，不能根据失败题不断改 Prompt 再称盲测。
当前测试题和参考事实公开存放在仓库中，因此它是可复现回归集，不是隐藏测试或抗污染基准。

检索可以索引 dev/test 对应的全部源文档，这是已知语料检索的设定，不等于训练时偷看测试答案。
索引输入只能是源文档 title/content；问题、意图标签、qrels、required_facts 标注数组和契约断言不得额外注入索引。
源文档正文自然包含待回答知识；禁止的是把题目及其答案标注作为额外检索提示。
自动校验包括重复 ID、规范化重复、分组跨集合、事实来源、引用文档和 Prompt 模板完全重叠。
这些检查不能识别所有语义近重复或标注错误；扩容时仍需人工检查同义改写与跨主题共享事实。

## 6. 指标输入与报告原则

预测使用 case_id 关联原题，status 只能为 ok、error、skipped；没有预测行计为 missing。
ok 只表示该次执行成功返回，不自动表示回答正确、工具成功或所有指标已经评判。
retrieved_document_ids、behavior、fact_checks、faithfulness_checks 和 citation_checks 必须来自实际观测或明确复核。
未观察到的字段省略或使用规范允许的 null，不能复制 gold、猜测行为或填默认 0.5。

每种指标单独报告 eligible、observed、分子、分母与覆盖率，不生成加权总分。
strict 指标以全部合格样本为分母，未测或失败不获分；observed 只描述已明确测量的部分。
observed=100% 而 coverage=10% 不代表全体表现；分母为 0 返回 null，即 N/A，不返回满分。
语义判断要求明确 judge_method，保留实际回答、证据、评判版本、错误和必要的复核记录。

## 7. 检索：Hit、Recall、MRR 与 nDCG

设第 i 题相关源文档集合为 R_i，返回列表是按排名排列的片段映射文档 ID。
K 计数原始片段位置；同一文档的重复片段消耗位置，但相关文档只在首次出现时获得一次增益。
G_i(K) 表示前 K 个位置命中的不同相关文档数量，r_i 表示前 K 内首次相关文档的原始排名。

- Hit_i@K = 1[G_i(K)>0]；Hit@K 是所有合格题 Hit_i@K 的均值。
- Recall_i@K = G_i(K)/|R_i|；Recall@K 在合格题上做宏平均。
- RR_i@K = 1/r_i；前 K 内无命中记 0，MRR@K 是 RR_i@K 的均值。
- DCG_i@K = Σ gain(r)/log2(r+1)，gain(r) 仅在首次遇到相关文档时为 1。
- IDCG_i@K = Σ 1/log2(r+1)，r 从 1 到 min(|R_i|,K)。
- nDCG_i@K = DCG_i@K/IDCG_i@K，再跨题平均；本集使用二元相关性。

例如 R={A,B}，返回 [A,A,X,B]，K=3：Hit=1、Recall=1/2、MRR=1。
重复 A 不再得分，B 在第 4 位不能计入前三位；该题 nDCG@3 约为 0.613。
Hit 只表示找到至少一份依据；多文档问题即使 Hit=1，也可能漏掉完成回答所需的另一份资料。
无答案和待澄清题没有普通检索 qrels，不计入上述分母，分别评回答行为。

排名单位必须一致：整篇文档 top-5 与片段 top-5 不是同一任务，不能直接当作检索改进证据。
本轮语料最长约 357 个字符，当前约 500 字切分规则下每文档一片；通用分块基线应保留 chunk→document 映射。
扩容后记录分块算法、长度、重叠、返回深度和 ranking_unit，不因去重后再截 K 而悄悄增加候选深度。

## 8. 意图、路由与回答行为

意图 Accuracy = 正确意图样本数 / 合格意图样本数。
每类 Precision=TP/(TP+FP)，Recall=TP/(TP+FN)，F1=2TP/(2TP+FP+FN)。
严格 Macro-F1 对本次 gold 有支持的类别取平均，缺失预测计为对应类别 FN；逐类 support 和标签范围同时报告。
observed Macro-F1 只对有已观测 gold 支持的类别平均，与 strict 的类别覆盖范围可能不同。
路由 exact-set accuracy 要求预测 Agent 集合与预期集合完全相等，顺序无关，多出或少一个均不算正确。
路由准确不代表工具执行成功；现阶段候选路由标签仍需独立复核。

answer 表示提供有依据的实质回答；clarify 表示先追问缺失的产品、版本或必要条件。
refuse 表示不确认无法获知的具体结论，可以解释限制并给出查询或安全下一步，不要求拒绝整个服务。
版本未明且规则互斥时应澄清；实时退款到账没有工具证据时，应说明不能确认，不能用政策时效推断已到账。
行为准确率按三类分别报告；期望 clarify 却预测 refuse，在当前严格口径下不能算正确。
合理的条件式回答等替代方式记录为标注分歧，经审查更新数据版本，不能临时放宽判据追分。
可回答题误拒答率 = 误预测 refuse 数 / 已观测行为的可回答题数，并同时显示该组覆盖率。

## 9. 参考事实覆盖、Faithfulness 与引用

参考事实使用 required_facts.id 逐项核验：true 为准确包含且保留条件，false 为遗漏或错误，null 为未完成评判。
严格参考事实覆盖 = 通过的参考事实数 / 全部必需参考事实数；已评事实通过率另以已评事实数为分母。
评判覆盖率 = 已评参考事实数 / 全部必需参考事实数；不能用关键词或数字碰巧出现代替语义判定。
它衡量参考答案完整性，无法发现答案新增的所有编造，因此不能命名为“整体事实正确率”。

[Ragas 官方 Faithfulness 定义](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/)关注回答主张与实际检索上下文的一致性。
Faithfulness = 被实际上下文支持的已评主张数 / 已评主张总数，另外报告样本覆盖与主张评判范围。
应覆盖实际回答中的新增数字、条件和执行承诺；只看知识库全集不能声称评了实际上下文忠实度。
faithfulness_checks 保存 assessed/supported；无可核验主张时 0/0 得分为 N/A，不能作为完美回答。
照抄错误上下文也可能获得高 Faithfulness，因此它与参考事实覆盖、来源可靠性和任务完成分开报告。

引用统计单位是主张而不是链接：required 为需要依据的主张，cited 为具有有效授权且版本匹配引用的主张。
assessed 为已核验引用支持性的主张，supported 为所引证据实际支持的主张。
引用覆盖率=cited/required；引用支持率=supported/assessed；引用评判覆盖率=assessed/cited。
约束为 supported≤assessed≤cited≤required；还需报告具有引用核验记录的样本比例。
只给正确的一句话加引用不能证明全篇证据完整；缺失核验的主张分母未知时，不能冒充严格全体比例。

## 10. 未来契约：业务完成与权限

24 条 workflow 和 24 条 security 只是未来验收合同，execution_tier=future_contract，不代表已运行通过。
审批、重启、重复提交、权限撤销等场景需建立前置状态、执行动作或故障注入，再查业务结果。
每项 assertion 使用 true/false/null；只有实际数据库、API、审计或事件证据才能支持 true。
任务通过要求该题全部必需断言为 true；部分断言正确或模型回复“成功”不能替代通过。
严格契约通过率=全断言通过任务数/全部合格契约数，完整评判通过率另以完整评判任务数为分母。
同时报告完整、部分和未评任务数，以及断言覆盖率；未实现或未执行保留 null，不包装成实测失败或成功。
真实工单任务还应核对编号、归属、状态、批准版本、业务幂等结果和重复记录数。
[τ-bench 论文](https://arxiv.org/html/2406.12045v1)的 pass^k 表示 k 次独立任务试验全部成功的可靠性，不是至少一次成功的 pass@k。

## 11. 失败、性能与费用

技术失败、业务拒绝、无答案与未测量必须分开；依赖降级说明不能作为正常检索片段计成功。
API 返回 200 也需检查结构化错误、fallback 和工具结果；不能把故障都解释为知识未命中。
空检索列表是已观测未命中；缺少检索字段是未观测，二者影响分母和覆盖率的方式不同。
异常率以实际尝试的 ok+error 为分母；skipped/missing 不是假想已执行请求。

延迟以明确边界的实测毫秒值统计，p50/p95 使用 nearest-rank，并保留样本数、错误请求及延迟覆盖率。
完整多轮回放耗时与单次末轮耗时分别说明；首事件时间、首 token 时间、最终完成耗时不能互换。
记录并发、到达速率、模型、输入输出长度、缓存、冷启动和限流；小样本 p95 不可外推容量。
费用使用真实 usage 和对应价格版本，包含改写、重排、摘要、画像及重试，离线 Judge 成本单列。
缺费用为未知，已知费用合计只是小计；不能把缺失调用当免费，也不能用字符数充当 token。

## 12. 运行隔离、复现与结果解释

离线 BM25 只运行标准库检索，不加载应用、不读取 .env、不调用当前 API 或模型，也不证明 ChromaDB 的效果。
查询采用预先声明的历史拼接协议，不使用 gold 查询改写；语料、题库、代码和分块配置的哈希随报告保存。
每次运行使用独立 run_id，保留预测、指标与配置，重复执行不能覆盖历史基线证据。
API 模式需要显式地址与隔离环境；每题使用独立会话和测试用户，避免画像、跨会话记忆与异步写入串题。
多轮 API 回放会生成真实助手回复，应声明它与固定历史检索的输入差异，保存实际轨迹。
应用未返回实际检索上下文、业务终态或 usage 时，对应指标保持未测，不从回复文字反推。

首版离线测试集可能取得很高的 Hit/Recall，这只反映 36 篇短小、主题清晰的虚构语料容易检索。
单份基线没有同条件改造前后对照，不能声称“优化提升”；最终数字以对应运行报告为准。
当前自动测试验证的是工具和指标实现，不是 276 题全部人工通过，也不是当前应用端到端成绩。

## 13. 扩容与后续验收路线

1. 先独立复核来源、事实和标签，对争议样本记录理由、修订版本，不把本轮抽查升级为全量人工核验。
2. 增加长文档、表格、代码、相似标题和多片段资料，检验真实分块、去重与融合问题。
3. 增加错误版本干扰、同义表达、跨文档条件组合、困难负例和自然多轮，保持来源家族划分。
4. 以授权公开产品文档建设另一份真实资料集，保存 URL、许可、产品版本、抓取时间和原文定位。
5. 将虚构政策集、公开资料集、授权真实业务集分开统计；新增生产数据须独立处理来源、脱敏和访问范围。
6. 在同一冻结集合、语料和排名单位上比较向量、BM25、融合、重排与按需改写，联合看质量、延迟和费用。
7. 业务实现后在隔离测试环境逐项执行 future_contract，补充真实断言证据，再更新验收状态。

候选问题数量不等于有效覆盖；扩容后仍按类别、来源、难度、版本和逐类 support 解释结果。
维护时同时更新 manifest、复核规范、预测格式与报告，明确区分“已构建、未复核、已运行、已评判、已部署”。
