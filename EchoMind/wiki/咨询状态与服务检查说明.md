# 咨询状态与服务检查

本次修正解决同一条退款政策咨询有时显示“转人工”的问题。原先 `BaseAgent` 从模型回答中搜索“转人工、人工客服、无法处理、specialist”等词，通用建议或否定句也会触发升级。现在升级建议来自请求的结构化人工升级意图、CRITICAL 紧急度及处理节点结果，单 Agent 与并行路径使用相同规则，并在 API 返回 `escalation_reasons`。政策咨询不会因为回答多写一句“可联系人工客服”而创建草稿。

当前状态含义：

- **AI 答复**：本轮没有人工升级建议，也没有等待确认的工单草稿。
- **建议人工核验**：有升级建议，尚未转交人工。
- **待确认工单**：业务库已经保存草稿，用户仍需核对并确认提交；不是人工已接单。

响应新增 `handoff_status`（`not_requested`、`recommended`、`pending_confirmation`），保留 `escalated` 兼容旧客户端。当前没有外部人工坐席接入，不能显示“已转人工”。旧咨询快照中的 `escalated` 可能来自原关键词规则，不代表真实交接；本次不篡改历史快照。

模型回答的措辞仍可能变化，同样的输入若对话历史、检索资料、意图或紧急度不同，处理决定也可能不同。回归测试固定这些条件，验证多种回答措辞不会改变业务决定；不声称真实模型每次逐字一致。没有检索到店铺条款时，通用建议不能代替已发布的店铺退款政策，应补充经过商家确认的知识资料。

管理员侧栏默认显示连接与服务数据。用户 ID、会话 ID、请求 ID 仅用于定位记录和排查日志，收在“排障信息”中，不再重复展示或允许手动修改。新会话由页面的清空操作及后端生成机制管理。

“检查连接”请求 `/health`，显示检查中、成功/失败、耗时和完成时间。只证明 HTTP 接口可达，不验证模型密钥、付费额度、知识库召回或回答质量。

“刷新服务数据”重新读取连接状态、知识片段数量、Skills 和运行统计，明确显示完成时间与失败的数据源。不会清空会话，也不会重新生成回答。轻量状态接口使用 10 秒超时，操作完成后恢复按钮；旧账号未完成的响应不能覆盖新账号界面。

“刷新统计”仅刷新服务进程的运行统计，并显示结果。所有后台请求继续执行原来的身份、角色和组织范围检查。
