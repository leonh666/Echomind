# 管理员与用户权限说明

更新：2026-10-22。本次改进继续使用原生 Python Orchestrator、FastAPI、SQLite 和 Vue，没有引入其他 Agent 框架。

登录后，管理员可以进入管理后台并查看全站用户目录，普通用户使用个人工作区。权限范围由服务端根据会话和数据库中的当前组织成员关系决定，前端隐藏入口只负责页面呈现。修改请求正文的 `user_id`、伪造角色或直接请求后台 URL 都不能取得管理员权限。

## 权限范围

`admin` 角色拥有全站账号目录的只读权限，可查看所有组织及自助注册的用户账号。用户目录仅包含编号、用户名、邮箱、显示名称、创建时间，以及组织编号、组织名称和该组织中的角色；不返回 API Key、密码哈希、密码盐或会话令牌。账号按用户去重后分页，未分配组织的账号也会显示。其他组织的工单、任务、咨询记录、知识库、诊断和审计仍按原有组织权限访问。普通用户不能通过注册、请求参数或修改前端角色获得管理员权限。

| 功能 | admin 管理员 | customer 普通用户 | support 客服 | kb_admin 知识库管理员 |
|---|---|---|---|---|
| 当前账号资料、自己的对话 | 允许 | 允许 | 允许 | 允许 |
| 咨询快照、检索来源与采纳反馈 | 本组织全部 | 仅自己的 | 本组织全部 | 仅自己的 |
| 业务诊断报告、统计与导出 | 本组织 | 不允许 | 不允许 | 不允许 |
| 草稿与工单查询 | 本组织全部 | 仅自己的 | 本组织全部 | 仅自己的 |
| 工单受理、状态更新 | 本组织 | 不允许 | 本组织 | 不允许 |
| 任务、工单审计接口 | 本组织 | 不允许 | 本组织 | 不允许 |
| 全站用户目录与用户总数 | 全站 | 不允许 | 不允许 | 不允许 |
| 业务总览与完整审计列表 | 本组织 | 不允许 | 不允许 | 不允许 |
| 后台会话索引、任务与工单分页列表 | 本组织 | 不允许 | 不允许 | 不允许 |
| 知识管理、检索调试与能力列表 | 本组织及授权公共知识 | 不允许 | 不允许 | 本组织及授权公共知识 |
| 评测报告、运行评测、回归基线 | 本组织 | 不允许 | 不允许 | 不允许 |
| 运行监控、工具 Trace、API 文档 | 允许 | 不允许 | 不允许 | 不允许 |

普通用户的聊天仍可以使用公共知识和本组织授权知识，并查看本次回答的参考来源；这不赋予知识库维护页面或检索调试接口的权限。普通用户创建草稿后，仍需独立核对和确认，模型不能代替用户提交工单。

后台会话页展示会话编号、所属用户、请求数和时间等索引信息，**不展示聊天全文**。用户、审计、会话、任务和工单支持分页，避免只展示默认前 50 条却误称“全部”。

新增“咨询与反馈”页面按上述权限展示已登录用户成功完成的回答全文与来源快照，与后台会话索引分开管理。普通用户在“我的咨询”只看本人记录，管理员的“客服诊断”报告严格按组织过滤。使用方式、数据记录范围与统计口径见 [证据反馈与诊断报告](证据反馈与诊断报告.md)。

`/monitor` 和 `/metrics` 是当前应用进程的运行聚合数据，并非按组织统计的业务指标；它们不能用于比较组织业务量。管理后台的用户总数是全站去重账号数，任务、工单、会话与审计计数按当前组织过滤，界面逐项注明范围。指标抓取专用凭据仅可访问 `/metrics`，不能调用其他后台接口。

## 创建演示账号

项目提供普通用户注册入口，使用用户名登录；没有默认管理员或默认密码。管理员及其他内部角色由具有服务器本地权限的维护者执行可信 CLI 开通，密码通过 `getpass` 在终端隐式输入，至少 12 个字符，不写入命令行参数。注册组织配置、旧账号用户名迁移见 [用户名登录与注册](用户名登录与注册.md)。

后端与前端整套 Compose 启动后，在 `EchoMindFrontend` 目录创建管理员：

```bash
docker compose exec echomind python -m business.auth --db /app/data/business/echomind.sqlite3 create-user --email admin@example.invalid --display-name DemoAdmin --organization-name Demo --role admin
```

保存输出中的 `organization_id`。创建普通用户时，复用该编号；把下例中的占位文字替换为真实组织编号：

```bash
docker compose exec echomind python -m business.auth --db /app/data/business/echomind.sqlite3 create-user --email customer@example.invalid --display-name DemoCustomer --organization-id "替换为上一步的组织编号" --role customer
```

不要再次使用 `--organization-name Demo` 来创建同组织用户，这会创建另一个独立组织。需要客服或知识库管理员时，同样复用组织编号，将 `--role` 分别设为 `support`、`kb_admin`，并使用不同邮箱。

本地不使用 Docker 时，在 `EchoMind` 后端目录运行同一 CLI：

```bash
python -m business.auth --db data/business/echomind.sqlite3 create-user --email admin@example.invalid --organization-name Demo --role admin
python -m business.auth --db data/business/echomind.sqlite3 create-user --email customer@example.invalid --organization-id "替换为上一步的组织编号" --role customer
```

CLI 的数据库路径必须与正在运行的 API 配置 `ECHOMIND_BUSINESS_DB_PATH` 完全一致。示例邮箱仅为占位数据，不是已创建账号。

## 监控抓取凭据

后台接口需要登录。即使将 `ECHOMIND_AUTH_REQUIRED=false` 用于旧版本地聊天调试，后台、知识维护、评测、监控和审计仍执行身份与角色校验。正常部署应保留 `ECHOMIND_AUTH_REQUIRED=true`。

Compose 使用独立的指标抓取凭据，而非管理员账号的登录令牌。首次启动前，在仓库根目录执行一次：

```bash
python -c "from pathlib import Path; import secrets; p=Path('EchoMind/.secrets/metrics_token'); p.parent.mkdir(exist_ok=True); f=p.open('x', encoding='utf-8'); f.write(secrets.token_urlsafe(48)+'\n'); f.close()"
```

命令使用系统安全随机源，凭据不会打印到终端；文件已存在时会报错并保留原值。保留此文件以供后续启动，不要每次重启时重新生成。`.secrets/`、真实 `.env` 和运行数据库不应提交到 GitHub。

Compose 将同一文件以 secret 挂载到 EchoMind 和 Prometheus 的 `/run/secrets/metrics_token`。EchoMind 通过 `ECHOMIND_METRICS_TOKEN_FILE` 读取，Prometheus 通过 `authorization.credentials_file` 以 Bearer 方式抓取。启动前未生成文件会导致 Compose 无法提供该 secret，需要先完成上一步。

两套 Compose 的 Redis（6379）、Chroma（8001）和 Prometheus（9090）宿主机端口都只绑定 `127.0.0.1`，防止从公网绕过应用权限直接读取知识、记忆或监控数据。后端容器仍通过内部网络的 `redis:6379`、`chromadb:8000` 连接依赖；Prometheus 仍通过 `echomind:8000` 抓取，无需开放这些数据管理端口。

维护者可在服务器本机访问 `http://127.0.0.1:9090`。远程查看 Prometheus 时，在自己的电脑执行 SSH 本地转发，将占位账号与服务器地址替换为自己的配置：

```bash
ssh -N -L 19090:127.0.0.1:9090 admin@your-server
```

保持该 SSH 会话后，在本机打开 `http://127.0.0.1:19090`。Redis 和 Chroma 的维护同样仅限服务器本机或受控 SSH 隧道，不应为普通用户重新开放公网端口。Prometheus 自带页面不承担 EchoMind 账号鉴权。

本地直接运行 API 时，可以让 `ECHOMIND_METRICS_TOKEN_FILE` 指向同一文件的绝对路径；也可以通过本机受保护的环境配置提供 `ECHOMIND_METRICS_TOKEN`。同时设置时文件优先；不要把真实值写入文档、命令历史、截图或公开配置模板。未配置专用凭据时，管理员仍可使用自己的已认证会话读取指标。

## 接口与验收

| 接口 | 数据范围 |
|---|---|
| GET `/auth/me` | 当前已认证账号的安全资料与当前组织身份 |
| GET `/admin/overview` | 当前组织业务计数和状态分布 |
| GET `/admin/users` | 管理员可读的全站用户允许字段列表，含各组织角色 |
| GET `/admin/activity` | 当前组织审计列表 |
| GET `/admin/conversations` | 当前组织会话索引 |
| GET `/admin/tasks`、`/admin/tickets` | 当前组织全部任务、工单的分页记录 |
| GET `/tasks`、`/tickets` 和详情接口 | 普通用户仅自己的，客服和管理员按组织授权 |

后台列表分页参数为 `limit`（1–100）和 `offset`（非负整数），返回 `items`、`total`、`limit`、`offset`。未登录访问受保护接口返回 401，已登录但角色不足返回 403。普通用户访问其他人的任务或工单返回 404，避免泄露记录是否存在。

本轮新增 `tests/test_admin_store.py`、`tests/test_admin_api.py` 的真实 SQLite 范围、HTTP 权限与字段检查，以及前端 `tests/admin.test.js`、`tests/access.test.js`、`tests/workspace-session.test.js` 的请求、分页、错误和身份切换测试。前端后台模块在身份改变、登录失效或权限撤销时清理已加载数据，并中止旧请求，避免旧身份的异步响应重新显示。

2026-10-22 本地验证：后端与评测包 381 项、前端 31 项通过，Vite 构建成功；隔离页面中验证了管理员跨用户查看与任务翻页、退出清空，以及客户仅查看本人资料和工单。条件与范围见 [验收记录](../docs/admin-permissions-verification.md)。这些结果不代表已完成云端部署、容器重建或真实依赖压测。复验顺序：

1. 普通用户登录，个人资料是当前账号，工单列表不包含同组织其他用户记录，页面无后台入口。
2. 使用普通用户凭据直接调用 `/admin/users`、`/monitor`、`/metrics`、知识维护、Trace 和评测接口，应返回 403。
3. 管理员登录，后台展示同组织多用户的数据；超过一页时可以翻页查看任务和工单。
4. 另一组织的管理员登录，不能读取前一组织的用户、业务记录或评测报告。
5. 管理员请求尚未完成时注销或切换普通账号，后台数据应立即消失，旧请求不能恢复显示。
6. 指标专用凭据可抓取 `/metrics`，调用 `/admin/users` 等其他后台接口应失败；无凭据的健康检查仍可用于就绪检测。
