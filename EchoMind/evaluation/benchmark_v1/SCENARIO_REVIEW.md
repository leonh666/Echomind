## 条件式回答如何计分

保留原有严格行为标签作为诊断，并新增 `behavior.acceptable_response`。例如版本未知时，回答可以是：

> 我还不知道你使用哪版。v1 的规则是……，v2 的规则是……；确认版本后才能确定哪条适用于你。

答案必须基于该题两版真实参考事实，并有以下三个语义核验结果：

```json
{
  "case_id": "rag-097",
  "status": "ok",
  "behavior": "answer",
  "behavior_checks": {
    "explicit_version_uncertainty": true,
    "both_version_rules_correct": true,
    "no_unjustified_version_selection": true
  }
}
```

这是格式示例，不是实际运行结果。核验值应来自人工或经过校准的 Judge，不能因为响应里出现“v1/v2”就自动赋 true。全部为 true 才接受替代回答；明确 false 为不通过，缺失或 null 为未核验，严格指标不给分且降低核验覆盖率。首选行为 clarify 仍按原协议处理；其他回答质量、Faithfulness 和引用指标继续单列。

## 契约范围

48 条仍是**尚未执行的验收规格**。`execution_tier=unexecuted_contract` 表示缺少统一执行器结果，不表示后端业务全部未实现。评分器兼容旧 future_contract 字段值，以便读取历史测试规格。

每条新增 `target_system`、`execution_status`、具体 preconditions / steps / outcome_oracle。不要求模型采用唯一工具顺序，但必须满足用户确认、归属、状态、幂等及权限要求。角色降级、超时、重试和故障只在独立环境测试。

## 尚需真实业务验证的部分

1. 合成规则的内部一致不等于真实平台政策；接入真实产品时要用授权、版本化来源另建 corpus，不能直接用于真实客服答复。
2. 多轮知识题主要是短追问，不能代表长期任务恢复或完整工单交互；后者依赖契约执行器与真实模型试运行。
3. 19 类题目分布接近平衡，不是线上请求分布；主场景与旧物流兼容切片分别报告。
4. 当前模型分类 Prompt 自身有 escalation/human_handoff 重叠示例，账号路由和时序词紧急度也存在上述差距；这是待修复的系统问题，不能通过改 gold 隐藏。
5. AI 复核不替代业务人员对规则、风险、合法替代答案和真实用户表达的独立确认。
